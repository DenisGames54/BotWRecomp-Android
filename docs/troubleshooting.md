# Troubleshooting

Consolidated from the README, commit history, and known workarounds in this
repo. Everything below was observed on the maintainer's test device unless
noted otherwise — **POCO F5 (Snapdragon 7+ Gen 2, Adreno 725)**, Debian ARM64
in a DroidSpaces container, Mesa Turnip 26.3 (Vulkan 1.4). Other devices and
drivers are unverified; please report what you find.

## Crashes

**Game crashes when a video plays (tower activation, cutscenes).**
The game needs the H.264 decoder this fork ports (`runtime/src/h264`,
generated by `tools/port_h264.py`). Without it, video scenes crash — e.g.
activating the first tower. If you built without the H.264 sources, rebuild
with them; tested at 60 fps with video and audio fine.

**Shader-compiler crash on Turnip.**
Cemu's non-IEEE multiply helper emits an `fmulz`/`fmadz` pattern that crashes
Turnip's shader compiler. This repo already works around it in
`LatteDecompilerEmitGLSL.cpp` (search for `// BotWRecomp:`). If you hit a
shader crash on a different driver version, check whether your Turnip build
predates the workaround and update Mesa.

**Crash reports.**
Recent builds print crash reports with real registers and a symbolized
backtrace — include the full report (not just the last lines) when filing an
issue.

## Performance

**Frame rates vary ~±15% between runs.**
This is expected and thermal/scheduler-related, not a bug in your build. The
maintainer's honest numbers on the POCO F5 (heavy open-world scene,
3000–5000 draws/frame): baseline 12–16 fps stock clocks; 17–23 fps with the
GPU clock locked at max; ~25–34 fps with a PGO build; up to 38–58 fps in
light scenes.

**Checklist before reporting "slow":**
1. Run via `linux/botw-run.sh` — it locks the GPU clock and pins threads to
   the big cores (there is also a CPU-affinity fix for the busiest thread and
   auto-detection of the fastest core; make sure you're on a recent build).
2. Try a PGO build (see the README's PGO section) — it roughly doubles heavy-
   scene fps on the test device.
3. Compare the same save spot and similar device temperature; note your
   driver version.

## Controls

**Touch layout.**
Recent builds include an in-game drawer (back button) with an edit/resettable
touch layout and quit, plus camera sensitivity scaling (`cam_sens` 0.3–3.0).
If touch input feels wrong, open the drawer and check the layout editor before
assuming a bug.

## Device and driver notes

- Only the POCO F5 / Adreno 725 / Turnip 26.3 combo above is tested. Other
  Adreno GPUs on Turnip will *probably* work; Mali and other drivers are
  unknown territory.
- The Linux ARM64 build targets Debian in DroidSpaces; there is no APK or
  installer yet, and breaking changes are expected.

## Before filing an issue

Include: device + SoC/GPU, driver name and version, build type (baseline/PGO,
commit hash), what you were doing (save spot/scene), and the full crash
report or log if there is one. Never include game files, dumps, keys, or
anything derived from the game (`generated/`, PGO profiles) — those must
never be committed or shared.
